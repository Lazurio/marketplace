# Lazurio Marketplace registry

The curated list of module templates that the Marketplace in Lazurio shows.
One record per template; adding a template is a pull request, and a curator's
merge is its listing. Lazurio reads the registry at one exact commit, so a new
template does not wait for a Lazurio release.

| Path | Holds |
| --- | --- |
| `offers/<publisher>/<id>.yaml` | one offer: the template's public repository, its card in Czech and English, and its releases |
| `schemas/offer.v1.schema.json` | the shape of an offer |
| `schemas/index.v1.schema.json` | the shape of `index.json` |
| `index.json` | every offer in one file, generated by `bun run index`; what Lazurio reads |
| `src/`, `scripts/`, `tests/` | the validator |

A listing is discovery information. It grants no access, installs nothing and
is no consent to publish: "Přidat do Organizace" in Lazurio hands an exact brief
to the person's agent, who follows the release's own `docs/adoption.md`.

## Releases and adoption

An offer lists its releases newest first. Each names its annotated tag
`v<version>` and the full commit the tag points to; a tag alone is not an
immutable identity. A release whose commit is still `null` is announced, not
published: Lazurio shows the offer but it cannot be adopted. Lazurio offers the
newest release whose commit is recorded. `artifactDigest` is reserved for the
digest of an attested release artifact.

`generation` (`app/v<N>`) is the offered release's app generation. It names
the data layer, not quality: v1 and v2 have no data of their own, v3 keeps
data in repository-db, v4 in a Dolt database on the Organization's server, v5
in a Dolt database hosted outside it. The release version (semver) is
independent of the generation.

`pricing` is reserved for paid templates; `free` is its only value.

## Checks

```sh
bun install
bun run check           # types, Biome, tests, offers and index.json; no network
bun run index           # regenerate index.json after changing offers/
bun run verify:sources  # each offer's repository and release on GitHub
```

CI runs `check` and `verify:sources` on every pull request and every Monday.
